# 设计文档（中文）

## 1. 设计目标
- 提供清晰、可用的线路规划交互：选起点/终点 → 一键规划 → 地图与列表同步展示
- 算法与数据解耦：支持从 `edges.csv` 明确定义道路/连接关系，也支持按经纬度自动生成边作为兜底
- 可部署、可复现：`docker compose up -d --build` 一键运行

## 2. API 设计

### 2.1 健康检查
- `GET /api/health`
- 返回：`{ status: "ok", time: "..." }`

### 2.2 节点列表
- `GET /api/nodes`
- 返回：节点数组 `[{ id, name, lat, lng, type?, desc? }, ...]`

### 2.3 最短路径
- `GET /api/path?from=<id>&to=<id>`
- 成功返回：
  - `startId` / `endId`
  - `totalDistanceMeters`
  - `pathNodeIds` / `pathNodes`
  - `segmentDistanceMeters`
- 失败返回：`{ error: "...中文错误信息..." }`

## 3. 前端交互设计

### 3.1 控制面板
- 起点/终点下拉选择（支持搜索）
- 交换起终点、清空选择
- 一键规划并展示总距离与路径节点列表

### 3.2 地图交互
- 渲染所有景点 Marker
- Marker Popup 支持“一键设为起点/终点”
- 规划成功后绘制路线 Polyline

## 4. 数据与容错设计

### 4.1 CSV 数据
- `nodes.csv`：必须存在且包含列 `id,name,lat,lng`（其他列可选）
- `edges.csv`：可选；至少包含 `from,to`；权重列支持：`distance_meters` / `weight_meters` / `distanceMeters` / `weightMeters`

### 4.2 容错策略
- 后端：`DataLoader` 对缺列/坏行进行跳过或给出明确的中文异常提示
- 前端：对节点 API 返回进行结构校验与清洗，避免脏数据触发运行时崩溃
- UI：ErrorBoundary 捕获不可预期异常并提示刷新重试

## 5. 性能与扩展
- 节点数量较小（景点级别）时，Dijkstra 在内存中运行即可满足交互性能
- 未来扩展点：
  - 引入真实道路网（大量边）时，可考虑启发式算法（A*）或预计算缓存
  - 为边增加更多权重维度（拥堵、票价、偏好等）
